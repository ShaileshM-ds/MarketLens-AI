--------------------------------

preflight later observed 2,604, a net increase of 32. The Phase 4C read-only
query found the collection changing during the query itself: the initial
collection-count pass returned 2,619, while subsequent analysis-specific
counts returned 2,623. This volatility prevents treating any one observed
count as a stable final total.

Application code in backend/app/workers/main.py confirms that an analysis
job calls analyze() and then upserts into analyses using
{product_id, cutoff, version} as the identity. For imported mode, cutoff is
the current time. The upsert sets created_at to the current time. Thus worker
analysis jobs can create new analysis documents when their cutoff differs
from existing identities and can update existing matching identities.
backend/app/services/normalize.py generates run-derived job IDs; this does
not add a run_id to analysis documents.

0). The exact computed run-derived jobs were observed in changing states:

observed 2,146 done and 9,642 queued, with the same 11,788 matched job
documents. Recent analysis records had created_at values after
2026-11-04T18:09:02Z. These observations, together with the worker's code
path, support that the running worker is processing analysis jobs and writing
analysis results. Recent worker logs contained no additional success-level
per-analysis detail; the code and database/job state changes provide the
evidence of activity.
