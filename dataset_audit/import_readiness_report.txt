MarketLens-AI import readiness assessment (planning only)
Audit scope: Downloads marketplace datasets and existing reports. No import or application/database change was performed.

Summary
- 1 of 11 files is already structurally canonical: mens_clothing_3_platform_dataset-1.csv. It is NOT import-ready until timezone semantics are resolved; product_url is blank for all 1,500 rows, and 168 stock_quantity values are blank (optional).
- 10 Amazon provider exports have explicit mapping candidates but are NOT ready for direct import. They need a staged transform, provenance preservation, nested seller-offer policy, and field-level validation.
- No dataset should be concatenated directly. Four final/snapshot pairs have near-complete cohort overlap; choose a source/capture policy before loading.
- No source file, existing report, application code, Docker configuration, or database was changed.

Required pre-import gates
1. Approve the 27-field mapping and whether import emits only Buy Box rows or also nested seller rows.
2. Confirm timezone for the synthetic clothing timestamps. Preserve explicit provider offsets and convert to UTC; never assume a zone.
3. Resolve missing-price rows (175 total), dead-page/redirect rows, and price conflicts without imputing a sale price.
4. Decide how to treat all negative provider discount values: compute a positive rate from validated original/final prices and retain raw signed input for audit.
5. Decide the authoritative file/capture for overlapping final/snapshot cohorts; retain capture timestamps if importing multiple genuine observations.
6. Define seller/listing identity and handle repeated nested seller+condition offers with different prices; no price- or array-index-based listing IDs.
7. Define category taxonomy and product/title conflict policy; review 322 ASIN overlaps with differing title/category values.
8. Preserve source filename/row, raw values, capture timestamp, import run and synthetic/scraped provenance. Keep optional unknown values null.
9. Run a dry-run transform and inspect accept/quarantine/duplicate counts before any separately authorized import.

Existing code changes that will eventually be needed
- Normalizer: it accepts INR already and converts major units to minor units (100x), so INR price support itself is present. It still needs a reviewed 27-column adapter; support explicit canonical product_id (especially shared MCL IDs across marketplaces), source/source_type/synthetic preservation, aliases/JSON parsing, seller-offer expansion/deduplication, and safe null/error handling. Its current product identity is marketplace+external_id+variant and would split a shared MCL product by marketplace. Its current source_type is derived from import mode, which can erase Synthetic provenance.
- History generator: currently USD-only both when selecting anchors and converting minor units back to major values. INR historical generation requires explicit INR eligibility, currency-aware minor-unit formatting/rounding and tests. Do not generate any history during migration, and do not present generated observations as observed source history.
- No backend/normalizer/history changes should be made until the mapping, identity and timezone gates are approved.
